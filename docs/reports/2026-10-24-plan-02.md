# Plan 2 report: app foundation

Branch `plan-02-app-foundation`. 11 tasks, each built test-first, reviewed, and attacked by the red team where it touched sign-in, money or data (Tasks 4, 5, 6, 10). A final whole-branch review on Opus was followed by one fix wave. At the end: 474 app tests and 291 server tests pass, the web build exports, and lint, typecheck and format are clean.

## What exists now

An Expo app (Android, iOS, web; SDK 58) that:
- signs in with an email code;
- walks through setup: income and payday; fixed costs with presets, edit and undo; savings with the reality check; money left until payday; personality; message times; notifications;
- shows Home with the animated Gullak and the daily budget from the server.

The + button is disabled until Plan 3 adds spend logging.

On the server:
- the pro-rated first cycle and `PUT /api/v1/budget/first-cycle`;
- a local-only dev endpoint for sign-in codes;
- a per-user lock so profile and fixed-cost writes can't race.

## Decisions taken, with reasons

| Decision | Why | Cost if wrong |
|---|---|---|
| Logs use an allow-list of field names; risky strings are dropped (emails, tokens, 6-digit runs, amounts, opaque runs, anything over 200 characters) | A deny-list leaked through arrays, odd keys and "Rs250" | A new log field must be added to the list on purpose |
| The API client owns the tokens: a generation number and a session epoch, single-flight refresh and sign-out | Late 401s, sign-out during refresh, and account switches could re-send a spent refresh token, which signs the user out everywhere, or mix accounts | None found; Opus re-checked with probes |
| The persisted offline cache is tagged with a hash of the user's email; a mismatched cache is discarded; sign-out waits for the wipe | The next person on the phone could see the previous user's figures | A first launch after reinstall shows no offline data |
| Sign-out clears per-user flags, the setup draft, the cache and scheduled notifications | "Leaves nothing behind" for a shared phone | None |
| The first cycle is budgeted from setup day; the pro-rated pool follows edits unless the user gave a money-left answer; the answer is money in hand now, capped at income | Spends before setup were counted against a pool that didn't include them | A user who answers then edits income keeps their stated figure |
| Home is `/home`; the root route is a redirect gate | Two routes claimed `/` | None |
| Message times run 7:00–11:00 am and 7:00–10:30 pm | Spec quiet hours are 11 pm–7 am | Fewer choices |
| An iOS reinstall that kept the keychain starts signed out; a storage read error keeps the session | Avoids a ghost session with no email, without signing people out on disk errors | A user upgrading from a pre-marker build signs in once more |

## Open for the founder

- **Refresh grace window (server).** A refresh that times out after the server already rotated the token signs the user out on every device at the next sign-out or refresh. This is common on Indian mobile networks. Decide before any public beta; it is planned for Plan 9.
