# Gullak V1: plan roadmap

The spec (`docs/superpowers/specs/2026-10-23-gullak-v1-design.md`) covers several subsystems, so the build is split into nine plans. Each produces working, tested software on its own. Plans 1 and 2 were written one after the other; Plans 3–9 were written up front and cross-checked against each other, and each is executed against the code that exists when it starts.

Migration blocks: each plan's migrations stay inside its block. If an earlier plan was executed with more migrations than planned, the later plan renumbers to the next free number in its own block.

Cross-plan names: the plan that provides a class, method or endpoint owns its name, and consuming plans use it. The badge hook is Plan 4's `in.gullak.gamification.BadgeTrigger.fire(UUID userId, String trigger, UUID refId)`, implemented by Plan 6's `BadgeService` and fired by Plans 4, 5 and 7. XP is Plan 3's `XpService.award(UUID, XpKind, String refType, UUID refId)`; Plans 4 and 5 append `XpKind` constants; Plan 6's job awards go through `XpLedger.awardOnce` on the same `xp_events` table.

Every task in every plan names its owner agent (`.claude/agents/`) and the test IDs it must make pass. The loop per task is in `docs/team.md`.
